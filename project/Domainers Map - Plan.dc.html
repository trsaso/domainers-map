Domainers Map

Architecture, schema, route and component inventories, build sequence and risks — followed by the design direction and links to the clickable prototype.

Assumptions
  • No existing codebase was connected — this is a greenfield plan. If a repo exists, the inventories below become a diff, not a spec.
  • Primary v1 user is the domain investor; brokers and buyers are secondary personas.
  • Seed data for the prototype is placeholder; swap data/seed.json for your export — the app reads only that shape.
Design reasoning
  • "Intelligence software" not "social network": dense, typographic, quiet. Colour is stroke, not fill — the only fills are match-score bars.
  • Dark-first app on a warm near-black; marketing and documents sit on paper. Same type (Cormorant Garamond display, Lora text, monospace for domains and prices).
  • The differentiator — domain → end-user buyer — is surfaced on every domain card and in a dedicated Matches view, not buried in a tab.

0 · Product structure (revised in round 3)

Reference screenshots showed a builder-community map whose engine is a points economy: visibility on the map is earned, rank is public, and paid plans buy reach — never rank. We adopt that engine but re-centre it on domainers: the unit of value is a domain with a price and a confirmed deal, not a product launch.

1 · Architecture proposal

One Next.js (App Router) monorepo on Supabase. Five seams, each independently deployable or replaceable later. Nothing talks to the database except the API layer; the matcher is a worker, not a request-time call.

Marketing
app/(marketing) — static, ISR. Landing, pricing, public profile pages (SEO).
App
app/(app) — auth-gated. Map explorer, directories, inventory, matches, leads, events, settings.
API & data
Route handlers + server actions over Supabase (Postgres, PostGIS, RLS, Storage, Auth). Typed with generated DB types.
Search & matching
Postgres FTS + trigram for search; pgvector embeddings + rules for buyer matching, computed by a queued worker.
Admin
app/(admin) — role-gated. Verification queue, moderation, sponsorships, data imports, audit log.
ConcernDecision
Folder structurefeatures/<map|directory|inventory|matching|leads|events|billing|admin>/ each with components/ · server/ · queries.ts · schema.ts; shared primitives in components/ui (shadcn) and lib/. No business data in components — everything comes through typed queries.
MapMapLibre GL JS with an OSM-compatible vector style (self-hosted or MapTiler/Protomaps — see risks). Server returns GeoJSON tiles via a /api/map/features route using ST_AsMVT at zoom ≥ 6 and pre-aggregated clusters below that; client-side cluster: true only for ≤ 5k features.
Auth & tenancySupabase Auth (magic link + Google). Every table carries workspace_id; RLS policies per role (member · broker · admin). Leads and notes are private to the workspace; profiles are public unless visibility = 'private'.
MatchingDeterministic rules first (wish-list, brand-name, TLD upgrade, keyword overlap, budget signal) producing a 0–100 score with reasons; embedding similarity as one weighted feature, never the whole score. Results cached in match_scores, recomputed on inventory or company change via pg_net → Edge Function queue.
Offers & outbidOpen offers with proxy bids on every listed domain; optional timed auction with reserve and soft close (+5 min on late bids). Resolution is a single Postgres function (place_offer) running in a transaction with row locks, so two simultaneous bids can't both lead. Outbid events fan out to notifications (in-app + email) via pg_net.
Verification tiersThree cumulative tiers: X (OAuth 2.0 link + account age ≥ 1 yr + one-time code in bio or post), DNS (TXT record on a sample of listed domains), Attested (a counterparty confirms a completed deal). Only DNS/Attested unlock full match scores and offer privileges above a threshold.
Reputation pointsComputed nightly by a worker from verification tier, profile completeness, priced listings, offers made/received, attested deals, RSVPs; decays 2%/month of inactivity. Points drive pin size, directory rank and badges — never match scores, never purchasable. Sponsorship stays a separate labelled mark.
Country viewAt zoom ≤ 3 the map renders a choropleth of member density with per-country counts (from a country_stats materialised view) and merged labels where countries collide; zooming in resolves to clusters, then pins.
State & data fetchingServer components for reads; TanStack Query for the map's live viewport queries; URL is the source of truth for filters (shareable searches).
ObservabilityStructured logs via pino; Sentry for client + server; Supabase log drains. Feature flags via a flags table, not env vars.

2 · Database schema

PostgreSQL with PostGIS and pgvector. All ids uuid, all tables have created_at · updated_at; soft deletes via deleted_at on user-generated rows. Locations are geography(Point, 4326) with a GiST index; city-level precision only, by design (privacy).

8Events + adminEvents CRUD, RSVPs; verification queue (all three tiers), offer disputes, moderation, audit log.
9MonetisationStripe: Country $4/mo (country-wide visibility whatever your rank, weekly X refresh) and World $12/mo (biggest pin worldwide, followed backlinks to landers, daily X refresh, portfolio-wide matches, profile views); brokerage sponsorships with visible marks. Sponsored map slots are auctioned: a fixed number of slots per region (e.g. 24), each holding one domain/brokerage card with its own monthly bid; anyone can outbid (next bid from current + $2/mo), the incumbent is notified and can raise; slots show "Sponsored · current bid · Outbid from $X" in the hover card. Rank is never sold.
10NetworkingConnections and messaging — only after §1–9 are stable.

6 · Risks & external dependencies

Dependency / riskImpactMitigation
Map tilesPublic OSM raster tiles are not for production traffic; a vector style needs a provider (MapTiler, Protomaps/PMTiles self-hosted, Stadia).Start with Protomaps PMTiles on Supabase Storage/Cloudflare; budget for a provider if traffic grows. Attribution always shown.
Company dataNo live company feed exists until a source is licensed (Crunchbase, PitchBook, Companies House, OpenCorporates).Phase 3 ships with CSV import + claim flow only. No integration is shown as connected until it is.
Embeddings / LLMCosts and vendor lock-in; hallucinated "reasons".Reasons come from rules; embeddings are one feature. Model version stored per score; swap-able provider behind one interface.
Location privacyInvestors may not want precise pins.City-level geocoding only; jitter within the city; profile-level visibility.
Data quality / fake profilesTrust is the product.Verification queue, DNS TXT domain ownership check, rate limits, report flow.
GeocodingNeeds a service (Nominatim policy limits, Mapbox, Google).Geocode once at write time, store the point; cache city centroids.
X (Twitter) APIOAuth 2.0 user auth is on the paid tiers and rate-limited; policy can change.Use X only to link a handle and read account age; never rely on it alone — DNS and attestation are the strong tiers. Fallback: paste a profile link + bio code checked manually.
Offers: shill bidding & non-paymentFake rivals inflate prices; winners vanish.Offers require DNS or Attested tier above a threshold; bidder history visible to sellers; escrow partner (Escrow.com API) for settlement; strikes reduce points.
"Refreshed from X" and post scoringReading a member's posts/bio needs X API read access (paid, rate-limited) or fragile scraping.Only fetch for paying plans at the promised cadence; cache aggressively; degrade to manual "Verify" button that checks one URL.
Lander badge crawlerDaily checks of up to 3 sites per member scale linearly.Edge function with HEAD + small GET, 24 h cache, exponential back-off; verify only members active in the last 30 days.
Points gamingSpam listings or self-dealt attestations to climb ranks.Attestations need both parties verified; per-kind caps; decay; anomaly flags to admin.
PaymentsStripe, tax (Stripe Tax), invoicing.Phase 9; feature-flagged.
EmailTransactional (Resend/Postmark) for auth and lead reminders.Supabase Auth email first; provider later.
Sponsorship vs. trustPaid placement can erode the "intelligence" positioning.Sponsored items are marked and capped per view; never alter match scores.
